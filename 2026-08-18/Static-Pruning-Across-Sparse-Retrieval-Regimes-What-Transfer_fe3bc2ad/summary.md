# 论文速读：Static-Pruning-Across-Sparse-Retrieval-Regimes-What-Transfer

## 一句话总结
本文首次系统评估了静态剪枝策略在不同稀疏神经检索引擎中的可移植性，发现索引侧剪枝（文档与倒排列表）跨引擎稳定有效，而查询剪枝常被现代引擎内置机制吸收；同时证明静态剪枝可与动态剪枝正交互补，并提炼出以NDCG@10饱和点（Recall@10约85–95%）作为通用工程停止准则。

## 研究问题与动机
- 稀疏神经检索模型（如SPLADE）通过逆序索引实现语义匹配，但显著增加查询延迟与内存开销，静态剪枝是工业界常用加速手段。
- 现有剪枝研究均在单一自定义全量打分管线中验证，未检验其结论在带有内置动态剪枝机制的现代生产引擎（如BMP、SEISMIC）中是否依然成立。
- 不同编码器产生的查询密度 regime 差异极大（如SPLADE平均激活44个查询词，V3-GTE仅约7个），剪枝收益是否受此 regime 支配尚不明确。
- 工程部署缺乏跨引擎统一的策略选择与停止准则，导致调参经验难以迁移，重复试错成本高。

## 核心贡献（创新点）
1. **跨引擎剪枝可移植性矩阵**：首次正交对比三种剪枝族与两种准则在三款架构迥异的引擎上的表现，明确“索引侧剪枝泛化、查询剪枝易被吸收”的边界规律。与前作仅在单管线验证的本质区别在于提供了引擎无关的部署决策依据。
2. **静态与动态剪枝的正交互补性证明**：通过2×2因子设计量化联合加速效果，揭示两者分别针对内存足迹与无效遍历瓶颈，叠加收益非冗余。区别于以往将静态/动态剪枝视为替代方案的认知，本文证明其为协同优化维度。
3. **可迁移的NDCG饱和停止准则**：发现NDCG@10在Recall@10仍处于85–95%区间时已平台化，且在浅层MS MARCO与深度TREC DL标注下均复现。该准则独立于具体引擎实现，为生产调参提供统一量化拐点。
4. **基于微架构剖析的内存受限假说验证**：设计三种accumulator变体（Φ/Ψ/Ξ）隔离内存访问与算术计算贡献，结合Linux perf指标证实稀疏检索瓶颈为内存带宽而非计算吞吐，从底层解释为何仅缩减内存足迹的剪枝具备跨引擎泛化性。

## 方法详解
- **剪枝策略族**：① 查询剪枝（在线）：按准则过滤查询词，减少需遍历的倒排列表数；② 文档剪枝（离线）：对每篇文档独立截断低权重项后再建索引，缩短所有倒排列表长度；③ 倒排列表剪枝（离线）：对每个term独立截断低impact posting，RAM节省最大但召回衰减更快。
- **裁剪准则**：α-Mass (AM) 保留权重降序累积达到总权重比例α的项，支持自适应支持集大小；Max-Ratio (MR) 保留权重≥τ·w_max的项，尺度不变且便于绘制连续Trade-off曲线。
- **引擎架构**：① 自研C++单线程全量管线（采用window-switch accumulator Ψ，工作集O(W)常驻缓存）；② BMP（Block-Max WAND引擎，内置β参数过滤低权重查询词）；③ SEISMIC（聚类倒排索引引擎，内置query_cut限制活跃词、heap_factor控制堆大小）。
- **微架构隔离实验**：在C++管线中固定索引与查询，仅更换累加器实现：Φ为全局数组散列累加（O(N)工作集，cache-hostile），Ψ为窗口局部累加（O(W)工作集，cache-friendly），Ξ为SIMD向量化乘加；配合Linux perf记录cache miss、dTLB miss、IPC，以证明延迟与内存访问量强相关（R²=0.84）。
- **互补性验证协议**：在BMP与SEISMIC上分别进行全/剪枝索引 × 全/剪枝查询的2×2因子实验，记录联合延迟与NDCG衰减。

## 实验与结果
- **数据集与编码器**：MS MARCO passage（~8.8M passages）与Natural Questions（~2.7M passages）；SPLADE（~44 query nnz）与V3-GTE（~6.9 query nnz），总计1,140组配置，另附TREC DL 2019/2020深度评判验证。
- **索引侧剪枝可移植性**：文档与倒排列表剪枝在所有引擎上稳定降低延迟（1.2–6.6×）与内存占用（18–82%），NDCG@10损失通常≤0.008；V3-GTE等稀疏查询 regime 下文档剪枝显著优于查询剪枝。
- **查询剪枝 regime 依赖**：C++全量管线中α-Mass查询剪枝可获4–11×加速，但在BMP（仅1.9×）与SEISMIC（1.05–1.31×）中因内置β/query_cut机制而收益大幅收窄。
- **静态+动态互补**：BMP上Doc AM 0.90 + Query MR 0.10联合剪枝达2.52×加速，NDCG@10仅下降0.003；SEISMIC上基线已近内存下界，联合加速仅1.39×，主收益转为索引体积缩减（−26%）。
- **NDCG停止准则**：三引擎两数据集上NDCG@10均在Recall@10约85–95%进入平台期；TREC DL深度标注验证表明该饱和非浅层qrels artifact，可作为跨引擎通用拐点。
- **最强结果**：BMP + Doc AM 0.90 + Query MR 0.10，延迟降至3,537 μs（baseline 8,915 μs），NDCG@10保持0.446（baseline 0.449），Recall@10为0.917。

## 相关工作脉络
- Lassance et al. [22]：系统性梳理学习型稀疏检索的静态剪枝，但仅在自定义全量管线验证。本文将其结论拓展至BMP/SEISMIC并检验跨引擎泛化边界。
- BMP [30] & SEISMIC [7]：分别代表Block-Max动态剪枝与聚类倒排索引两种主流生产架构，已内置查询词过滤。本文首次检验外部静态剪枝与其内置机制的重叠与互补关系。
- WAND / Block-Max WAND [6, 14]：动态剪枝基础算法，通过上界估计跳过非竞争文档块。本文从“内存受限”视角统一解释静态剪枝为何能与其协同而非冲突。
- 传统静态剪枝文献 [4, 5, 8, 10, 11, 13, 31]：基于概率/信息论或频次统计的倒排索引裁剪方法。本文指出学习型稀疏分布偏离标准Zipfian，需重新评估经典结论在现代engine上的适用性。
- PISA [29] / DSP [9] / SINDI [23]：其他高性能稀疏检索引擎。本文虽未直接评测，但提供的内存-遍历正交分解框架可作为后续引擎剪枝移植的通用参照基准。
