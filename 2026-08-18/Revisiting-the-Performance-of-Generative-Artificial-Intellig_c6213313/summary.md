# 论文速读：Revisiting the Performance of Generative Artificial Intelligence on Introductory Object-Oriented Programming Assessments: Insights from 2026

## 一句话总结
本文对 ChatGPT-5.2、DeepSeek-V3、Gemini 2.5 Flash、Claude Sonnet 4.5、M365 Copilot 五个主流生成式 AI 系统在爱沙尼亚大学 Java 面向对象编程（OOP）课程的真实编程测试与期末考试中的表现进行了系统性评估，并与历史学生成绩及一年前的评估结果进行纵向对比，发现系统整体成绩已显著优于学生平均水平，但在接口/抽象类等概念性主题与图形视觉推理上仍存在持续痛点。

## 研究问题与动机
- **核心问题**：当前先进 GenAI 系统在真实的入门级面向对象编程评估中表现如何？其反复出现的错误模式与能力边界是什么？
- **动机1**：GenAI 在编程教育与软件开发中的渗透日益加深，学生对 AI 辅助编程的使用极为普遍（课程内 87.8% 的学生曾使用），但针对 Java OOP 这一核心门槛概念的专项、系统性评估仍十分匮乏。
- **动机2**：现有研究高度集中于英语提示下的基础编程题，对非英语（如爱沙尼亚语）OO 课程真实考核场景的考察不足，难以反映实际学习情境。
- **动机3**：GenAI 能力迭代极快，基于前一年模型得出的结论容易过时，亟需基于同一套标准化、真实考试任务的纵向复测，以刻画性能演进轨迹。
- **动机4**：过往工作常局限于 ChatGPT 单模型，且鲜有研究同时对比多系统在一套完整课程评估体系中的综合表现与共性弱点。

## 核心贡献（创新点）
1. **真实 OO 场景的基准评估**：基于坦佩雷大学 Java OOP 课程的两轮编程测试与一次期末考试，提供了对五个主流 GenAI 系统的首个大规模真实教学评估基线。与已有工作主要依赖合成或竞赛题目的本质区别在于，本文评估任务来源于真实课程大纲与学习成果要求，更能反映课堂可用性。
2. **两年期的纵向对比设计**：在同一套题目、同一套评分标准下，将 2026 年结果与 2025 年同等条件下 ChatGPT/Copilot 的分数与错误模式进行对比，揭示了模型快速进化事实与仍顽固存在的薄弱环节之间的反差，这一纵向视角在同类研究中较为少见。
3. **多模型共性错误谱系挖掘**：不仅关注总分排名，还归纳了跨模型的共性问题，包括对接口与抽象类规则（extends/implements/@Override/抽象方法约束）的混淆、对隐式任务约束的忽视、以及在图形截图解读上的系统性失败，为后续课程设计、评测基准构建与模型对齐训练提供结构化诊断依据。

## 方法详解
- **研究对象与采样**：选取学生报告中最高频使用的五款免费/免费访问型 GenAI 系统：ChatGPT-5.2、DeepSeek-V3、Gemini 2.5 Flash、Claude Sonnet 4.5、M365 Copilot。
- **评估任务来源**：直接使用坦佩雷大学“面向对象编程”课程的原版编程测试（Test 1、Test 2）与期末机考题库片段，题目全部为爱沙尼亚语，涵盖类与对象、继承、接口、抽象类、流、异常、集合、事件处理、JavaFX 图形输出识别及综合简答/填空任务。
- **输入与交互策略**：不做任何翻译、改写或提示词工程；对每道题只输入原样题干与要求；不对 AI 进行追问、迭代修正或二次提示，仅采集每次生成器的首次响应，以贴近学习者“一次性贴题”的真实使用范式。
- **评分机制**：沿用课程既定的学生评分量规——编程题按所需类、方法、功能完整性与编译通过情况计分，编译失败记 0 分；客观/填空题按预设正确答案给分，允许部分给分。每道测试题由授课教师按统一标准进行人工阅卷。
- **对照基线**：
  - 历史学生成绩：同课程近三年学生的平均分与中位数。
  - 历史 AI 成绩：使用 2025 年同一批测试/题目（针对 ChatGPT 与 Copilot）的相同评估记录，以保证纵向可比性。
- **数据分析维度**：除总分对比外，还逐项统计每道考题的得分分布、常见错误类型，并对比两次评测之间的迁移误差变化。

## 实验与结果
- **编程测试 1（满分 16 分，及格线 12 分）**：学生均分 14.61（SD=3.11），中位数 15.7。ChatGPT-5.2 平均 15.75、DeepSeek-V3 平均 15.75、Gemini 2.5 Flash 平均 16（满分）、Claude Sonnet 4.5 平均 16；M365 Copilot 平均 10.67，受单次编译失败导致 0 分拖累。相比 2025 年，ChatGPT 与 DeepSeek 保持稳定高位，Copilot 因单次语法错误拉低均值。
- **编程测试 2（满分 16 分）**：学生均分 13.39（SD=3.59），中位数 14.75。ChatGPT 平均 15、DeepSeek 平均 15.67、Gemini 平均 16、Copilot 平均 16；Claude 因漏掉 import 导致零分但修正后应满分。与 2025 年对比，ChatGPT 从约 12.13 升至 15，Copilot 从 14.87 升至 16，提升明显。
- **期末考试（满分 36 分）**：学生均分 26.90（SD=3.62），中位数 27.33。AI 最高为 Claude 30.95、ChatGPT 31.01、Gemini 30.73、Copilot 29.49、DeepSeek 29.50；无一进入学生前 10%。相较 2025 年，ChatGPT 从 23.82 跃升至 31.01，Copilot 从 27.13 提升至 29.49，均突破上四分位；仅 DeepSeek 略低于上四分位。
- **错误模式归纳**：
  - 接口/抽象类相关：多个模型混淆 extends/implements、误以为抽象类实现接口必须实现所有方法、对 @Override 作用范围与接口内 abstract 关键字存在误解、对访问修饰符规则失准。
  - 任务约束理解不全：在多解答题中仅给出单一答案、忽略隐式可见性/文件编码等附加要求、过度生成未请求的方法或字段。
  - 视觉/图形题：涉及 JavaFX 截图的题目几乎全军覆没，得分 0-1.4 之间，表明图文对齐与界面推理能力仍薄弱。
  - 流与文件：对 readInt/writeInt 与 readUTF/writeUTF 不可混用这一点理解不足。
  - 异常处理：部分模型错误认为一次 try 下多个 catch 能连续捕获在 catch 内部抛出的异常。
- **最强结果与提升幅度**： Gemini 在两次编程测试中多次获得满分；Claude 在期末考试中取得最高均分 30.95；最显著纵向提升来自 ChatGPT，期末分从 23.82 提升至 31.01，增幅约 30%，且多项上一年高频错误消失。

## 相关工作脉络
- **Lepp & Kaimre (CSEDU 2025)**：同一课程团队的一年前评估，本文在此基础上扩展至五模型并采用更全面的题目与详细错误谱系，直接构成纵向对照。
- **Raihan 等 (SIGCSE TS 2025)**：系统综述指出 125 篇 GenAI+CS 教育文献中仅有 4 篇聚焦 OOP，印证了本研究的领域空白与必要性。
- **Cipriano & Alves (ICSE 2024)**：发现早期 GPT-3.5/GPT-4/Bard 在 Java OOP 实现中存在 instanceof 误用、接口实现不完整等问题，本文延续该主题但在更新模型上验证其是否缓解，并补充非英语语境证据。
- **Ouh 等 (2023) / Cámara 等 (2023)**：分别揭示 ChatGPT 对 UML/可视化软件工程产物理解的局限，本文进一步确认在真实 JavaFX 图像题上的同类短板。
- **Malinka 等 (2023)**：评估捷克语信息安全课程中 ChatGPT 表现参差；本文在爱沙尼亚语 Java OOP 考试中取得更稳定高分，提示学科与题型可能显著影响多语言稳定性。
- **Bordt & Luxburg (2023)**：发现 ChatGPT-3.5 未通过数据结构课程而 ChatGPT-4 接近学生平均；本文结果进一步显示当前旗舰模型已全面反超入门 OO 学生平均，印证快速迭代态势。

## 局限性与未来方向
- **样本与场景局限**：仅覆盖一所高校的一门 Java OOP 基础课，跨课程、跨语言、跨难度梯度的外推性需谨慎。
- **单次响应约束**：仅评测第一次输出，未探索多轮提示、自我修正与工具链协同潜力，可能低估实际可用上限。
- **提示敏感性**：题干语言、排版和隐性约束的表达方式会显著影响结果，本研究为控制变量牺牲了部分生态效度。
- **评判主观性**：编程题人工评分虽使用统一量规，但对代码风格、额外实现等判定仍存一定主观空间。
- **未来方向**：
  1) 扩展到 Python、C++ 等不同语言与更高级别课程；
  2) 引入多轮迭代、搜索与沙箱执行等真实教学场景流程；
  3) 开展针对接口/抽象类等顽固错误的模型微调与对齐研究；
  4) 系统比较 AI 错误与学生典型迷思概念的同构性，反哺教学设计；
  5) 建立开放的多语言 OO 动态评测基准与年度追踪协议。

## 研究启发与可借鉴点
- **纵向复测范式**：以固定课程、固定题目、固定评分的“同卷复测”设计追踪模型能力变化，值得在更大范围内推广为标准做法。
- **首次响应优先评估**：剔除提示工程干扰，贴近学生真实使用习惯，可作为教育场景下公平对比的默认指标。
- **错误谱系驱动的教学设计**：将 AI 高频错误与初学者迷思并列分析，有助于设计针对性练习（如接口/抽象类辨析、可见性与重写规则、流格式匹配）。
- **多模型横向对照**：同题同评、多系统并行的做法提高了结论稳健性，避免单一模型结论被架构差异绑架。
- **跨语言可行性验证**：在非英语题干下仍保持高准确率，为多语言环境下推广 AI 辅助编程教学提供实证依据。

## 关键术语表
- **生成式人工智能（GenAI）**：能够基于学习到的数据分布自动生成文本、代码、图像等新型内容的 AI 系统总称。
- **大型语言模型（LLM）**：基于 Transformer 等架构、以海量文本预训练的大规模参数模型，具备理解与生成自然语言及代码的能力。
- **面向对象编程（OOP）**：以类和对象为核心抽象，封装数据与行为，并通过继承、多态、接口等机制组织程序的结构化编程范式。
- **提示工程**：通过设计输入提示的结构、措辞与示例，引导 LLM 输出符合预期的结果的技术与方法。
- **纵向评估**：在多个时间点对同一或等价任务重复评估，以刻画模型或群体能力随时间演化的研究方法。
- **门槛概念（Threshold concept）**：学习某一学科时必须掌握的、能从根本上改变认知方式的关键概念，掌握后常产生持久的认知转变。
- **JavaFX**：Oracle 推出的用于构建富客户端桌面应用的 Java UI 工具包，常用于教学中演示事件与图形渲染。
- **Comparable / Comparator**：Java 中两种排序契约，前者由类自身实现以定义自然顺序，后者以外部函数式策略实现自定义比较。

## 可复现要素
- **数据集**：坦佩雷大学 Java OOP 课程的原始编程测试与期末考题片段；数据可向通讯作者申请获取（Data Availability Statement 已说明）。
- **代码/权重**：论文未公开评测脚本与模型权重，评估基于官方 API 的默认设置。
- **关键超参/设置**：未显式设定温度、top-p、最大生成长度等超参，所有模型均使用默认参数；仅采集首次生成响应，不做迭代。
- **评估协议**：使用课程既定评分量规，由授课教师按统一标准人工评分；相同题目复用于 2025 与 2026 两年对比。
- **语言环境**：全部题目与提示保持爱沙尼亚语原版，未做翻译或本地化处理。
