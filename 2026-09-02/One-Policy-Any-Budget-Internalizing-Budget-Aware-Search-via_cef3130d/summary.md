# 论文速读：One-Policy-Any-Budget-Internalizing-Budget-Aware-Search-via

## 一句话总结
本文提出了 AnySearch 框架，通过两阶段课程强化学习（含显式脚手架渐进移除与自适应预算采样）将预算感知搜索能力内化至单一策略，使模型能在任意搜索预算约束下自适应调整检索分配，无需额外训练或外部追踪器即可实现准确率与工具效率的双重提升。

## 研究问题与动机
- **部署预算多变性矛盾**：实际场景中搜索预算动态变化（如低延迟场景限流 vs. 深度研究场景允许充分探索），但现有 RL 搜索代理训练于固定预算，部署时无法自适应调整。
- **外部依赖局限**：BATS 等基线依赖独立预算追踪器，将预算感知能力外置为系统依赖，而非模型内生能力；此类方法在预算切换时需重新配置，缺乏泛化性。
- **训练推理鸿沟**：现有方法缺乏显式预算状态引导，模型难以学会在有限预算下区分"可通过推理解决"与"需外部检索"的问题边界，导致低预算下效率骤降。
- **效率与准确率的权衡困境**：单纯优化答案正确率会导致冗余搜索，而仅惩罚搜索次数可能损害复杂多跳问题的求解能力，需设计联合奖励机制平衡二者。

## 核心贡献（创新点）
1. **渐进式脚手架内化机制**：首次提出将显式预算状态注入与结构化推理提示作为训练脚手架，通过两阶段课程学习逐步移除，实现预算感知能力的策略内化，消除部署时对外部追踪器的依赖。
2. **滑动窗口自适应预算采样**：设计基于最新轨迹准确率动态调整预算采样概率的机制（公式4），自动聚焦模型薄弱预算层级，避免均匀采样导致的低预算训练不足或高预算过拟合。
3. **自适应效率权重复合奖励**：创新性地设计按查询难度动态调节的效率奖励权重（公式9），在已掌握的高准确率查询上强化预算节省激励，在困难查询上优先保障答案正确性，破解效率-准确率权衡难题。

## 方法详解
**核心架构**：采用 GRPO 强化学习框架，将预算感知搜索建模为资源受限序列决策问题（公式2）。

1. **预算状态注入**：每轮交互前强制注入 `<budget>` 标签明确剩余/已用/总预算（公式），使模型显式感知资源约束。
2. **双因素结构化推理**：在 `<think>` 块中要求模型分析信息充分性与预算适应性策略，建立预算约束下的决策先验。
3. **两阶段课程学习**：
   - Phase I：线性衰减预算（B_max→1）配合完整脚手架，共100步完成预算感知模式初始化；
   - Phase II：移除脚手架，启用自适应预算采样（λ=0.6平滑混合），利用滑动窗口（W=20）统计各预算层级准确率动态调整采样概率（公式4）。
4. **复合奖励设计**：
   - 绝对效率信号 $R_{abs}$：正确回答时奖励比例与节省预算成正比（公式7）；
   - 相对效率信号 $R_{rel}$：与同组最优正确轨迹比较（公式8）；
   - 自适应权重 $\gamma_q$：按组内平均准确率缩放效率奖励（公式9），实现难度感知权衡。

## 实验与结果
**数据集**：训练集 NQ（79k）+ HotpotQA（90k）；测试集覆盖7个基准：NQ、TriviaQA、PopQA、HotpotQA、2Wiki、MuSiQue、Bamboogle。

**关键结果**：
- 主实验（Qwen2.5-7B-Instruct, B=5）：AnySearch 平均 EM 达 0.431，较最强基线 StepSearch（0.403）提升 6.9%，在 Bamboogle 上以 0.398 对比 0.328 实现 21.3% 绝对增益。
- 跨预算泛化：在未见预算 B=6~8 上持续单调提升（Bamboogle B=8 时达 0.42 vs. Search-R1 的 0.37），验证内化能力。
- 工具生产率（TP）：Qwen2.5-7B B=6 时 TP=0.354，较 Search-R1 的 0.212 提升 66.9%，显著降低检索成本。
- 消融验证：完整设计比移除脚手架（No Scaffold）平均提升 8.4%，自适应采样（λ=0.6）优于均匀采样（λ=1）5.2%。

## 相关工作脉络
- **BATS（Liu et al., 2025）**：引入预算状态追踪但依赖外部模块，AnySearch 将其能力内化至策略网络，消除部署依赖。
- **Search-R1（Jin et al., 2025）**：纯结果导向 RL 搜索代理，缺乏预算感知机制；AnySearch 扩展其奖励空间为双目标优化。
- **StepSearch（Wang et al., 2025b）**：步骤级监督降低奖励稀疏性，但未考虑预算约束动态变化；AnySearch 在其基础上增加预算条件。
- **ZeroSearch（Sun et al., 2025）**：用模拟检索替代真实搜索降低成本，AnySearch 验证其在真实搜索场景的有效性并扩展至任意预算。
- **BudgetThinker（Wen et al., 2025）**：针对 token 预算而非工具调用预算，AnySearch 首次解决工具调用预算自适应问题。

## 局限性与未来方向
- **预算维度单一**：仅建模为搜索调用次数，未纳入延迟、成本等多维资源约束，未来可扩展为连续多目标优化。
- **知识库依赖瓶颈**：模型无法检索超出参数知识与维基百科覆盖范围的答案，需结合动态知识更新机制。
- **静态语料限制**：使用 2018 年 Wikipedia 快照，未评估时序适应性，开放网络实时更新场景待验证。
- **计算成本假设**：当前假设搜索成本远高于生成 token，实际中需根据具体 API 定价动态调整奖励权重。

## 研究启发与可借鉴点
- **脚手架渐进移除范式**：为其他依赖外部引导的 Agent 任务（如代码生成、多模态推理）提供可迁移的训练策略设计模板。
- **自适应采样窗口设计**：滑动窗口准确率统计与混合均匀分布的方法，可复用至超参数搜索、多任务学习等资源分配场景。
- **难度感知奖励缩放**：通过群体准确率动态调节奖励权重的思路，适用于大模型对齐中的偏好优化、奖励建模等需要平衡安全与性能的任务。
- **成本结构敏感化**：明确搜索调用与 token 生成的成本量级差异（Table 9），提示在 Agent 训练中需根据实际部署成本定制奖励函数。

## 关键术语表
**Internalization（内化）**：将外部辅助机制（如预算追踪器）转化为策略网络内生能力，消除部署时对外部依赖的过程。
**Scaffold（脚手架）**：训练初期提供的结构化引导（如显式状态注入、提示模板），随训练逐步移除以培养自主决策能力。
**Curriculum RL（课程强化学习）**：按学习难度递进设计训练任务序列，加速策略收敛并提升泛化能力的训练范式。
**Tool Productivity（工具生产率）**：衡量每单位工具调用所获得的正确回答数，反映资源利用效率的核心指标。
**Adaptive Weighting（自适应加权）**：根据查询难度动态调整奖励成分权重的机制，平衡不同目标间的竞争关系。
**Sliding Window Sampling（滑动窗口采样）**：基于最近 W 条轨迹的统计量动态调整采样分布，聚焦模型薄弱环节的训练策略。
