# 论文速读：NetlistBench-Evaluating-LLM-Reliability-in-SPICE-Netlist-Recognition-and-Manipulation

## 一句话总结
本文提出了 NetlistBench，一个面向 SPICE 网表的结构化验证基准，系统评估 LLM 在网表识别与操纵任务上的可靠性，揭示当前模型在结构性操作和长链路复合编辑中存在显著的性能瓶颈。

## 研究问题与动机
1. **LLM 在网表层面的可靠性未知**：LLM 已广泛用于 IC 设计流程（网表生成、仿真优化、网表→原理图转换等），但这些工作流均以 SPICE 网表作为共享表示层，而模型在该底层表征的操作可靠性从未被系统量化。
2. **现有评估混淆了高层推理与低层操作**：已有基准（如 AMSbench、CIRCUIT）关注端到端结果（语法有效性、仿真成功率、规范改进），无法区分失败源于高层设计推理缺陷还是低层网表损坏。
3. **通用代码基准不适用于电路表示**：SWE-bench 等通用代码基准依赖单元测试，但无法捕捉 SPICE 网表特有的设备端接语义、共享节点连接性、有序子电路接口等结构性质。
4. **网表编辑失败具有独特性**：SPICE 网表中电气连接性通过节点名共享隐式编码，而非显式端子-端子链接，正确编辑需同时维护端子角色绑定、节点身份和局部性约束，这对普通文本建模构成特殊挑战。

## 核心贡献（创新点）
1. **将 SPICE 网表可靠性形式化为表征层面评估问题**：首次将网表识别与操作可靠性从高层设计推理中剥离，聚焦模型能否将网表作为结构化电路工件正确处理。与已有工作本质区别：不评估最终仿真结果，而是评估中间表示层面的结构保真度。
2. **提出 NetlistBench 结构化验证基准**：包含 2,342 个案例、24 个任务族，覆盖参数/连接性识别与编辑、层次操作、等价判断和长链路复合编辑。与已有基准本质区别：基于确定性规范电路表示（canonical IR）而非字符串相似度或仿真进行验证。
3. **开发结构感知评估预言机（Structure-Aware Oracle）**：将模型输出和参考答案解析为规范化 IR，执行包含设备名、有序端子绑定、参数归一化、对称无源器件和无序端子比较的精确匹配。与已有工作本质区别：直接检测改名未变节点、多余/缺失设备、无关参数扰动等结构性错误，而非仅检查语法。
4. **揭示"结构保持瓶颈"现象**：发现简单局部编辑准确率达 96%–100%，但设备添加降至 41%–83%、等价判断降至 49%–90%，且随编辑步数增加准确率急剧下降（15 步复合编辑接近 0%），证明高可靠性不等于多步变换可靠性。

## 方法详解

### 基准数据来源与构造
- **AnalogGenie**（2,838 个扁平 CMOS 模拟网表）：Simple（中位 5 器件）、Medium（中位 20 器件）、Complex（中位 36 器件，最大 69 器件）。
- **ALIGN**（931 个层次模拟网表）：含 21 种拓扑族，每个网表 3–4 个子电路。
- 实例构造采用确定性模板驱动流水线，每个案例为三元组 $(N_{src}^{(i)}, T_{inst}^{(i)}, Y_{target}^{(i)})$，确保指令无歧义、ground truth 可复现。

### 24 个任务族设计
- **识别模态**（800 案例，8 个族）：器件参数提取、语义端子连接性、有序端子连接性、节点关联、子电路端口、实例端口映射、端子邻居关联、等价判断。
- **操作模态**（1,542 案例，16 个族）：
  - 6 个单步编辑：连接性编辑、器件添加/移除/替换、参数编辑、重命名传播。
  - 5 个扁平复合族：3/6/9/12/15 步相互依赖编辑。
  - 5 个层次复合族：子电路展开、端口交换、子电路复合编辑。

### 结构感知评估预言机
核心是将网表和参考答案均解析为**规范电路表示（Canonical IR）**，比较规则如下：
- 设备集完全一致（无多余/缺失器件）。
- 每个器件的实例名、器件类型、**有序端子节点绑定**、参数完全一致（数值归一化，如 1k = 1000）。
- 顶层 directives 一致。
- 对称两_terminal 无源器件（R/C/L）端子视为无序。
- 子电路定义必须在端口接口（端口顺序视为语义，除提取任务外）、内部器件和 directives 上一致。
- 等价判断任务使用 VF2 图同构算法验证标签正确性（仅用于验证 ground truth，不参与模型评分）。

## 实验与结果

### 数据集
- 总计 **2,342 个案例**，来自 AnalogGenie（2,838 扁平）和 ALIGN（931 层次）两个源。

### 评估基线
六款非思考型 LLM：Claude Sonnet 4.6、GPT-4.1、Gemini 2.5 Flash、DeepSeek-V4-Flash、Qwen3.6-Flash、Qwen3-30B-A3B；另单独评估 DeepSeek-V4-Flash 开启推理模式（DS+R）。

### 主要结果
| 任务类别 | 最高准确率 | 最低准确率 | 关键数字 |
|---|---|---|---|
| 器件移除 / 参数编辑 | 100%（Claude） | 96%（Qwen3-30B） | 简单局部操作最可靠 |
| 器件添加 | 83%（Claude） | 41%（DeepSeek-V4） | 引入新结构时显著下降 |
| 等价判断 | 90%（Claude） | 49%（DeepSeek-V4） | 结构性推理薄弱 |
| 扁平复合 3 步 | 80%（Claude） | 28%（Qwen3-30B） | — |
| 扁平复合 15 步 | 34%（GPT-4.1） | 0%（Qwen3.6/DeepSeek） | 长链路误差快速累积 |
| 层次子电路复合 9 步 | 43%（Claude） | 1%（Qwen） | 层次操作同样脆弱 |
| **总体（非思考型）** | **82%（Claude）** | **41%（Qwen3-30B）** | — |
| DS+R 推理模式 vs 非思考 | 81% vs 55% | — | 推理提升显著但不彻底 |

### 关键发现
1. **推理模式有效但不根本**：DeepSeek-V4-Flash 从 55% 提升至 81%（p<10⁻⁶），但 15 步复合编辑仍降至 31%。
2. **PySpice 表示仅对小部分模型有帮助**：对 DeepSeek-V4-Flash 有显著提升（p<0.001），但对 Qwen3.6-Flash 无显著改善（p=0.51）。
3. **误差模式以结构性错误为主**：识别输出通常符合 JSON schema 但电路事实错误；操作失败主要表现为遗漏编辑、重复编辑、局部性丢失、无关端子重新绑定和拓扑漂移。

## 相关工作脉络
1. **AMSbench（Shi et al., 2025）**：评估多模态 LLM 在 AMS 电路领域的综合推理能力（拓扑推理、原理图理解等）。NetlistBench 定位差异：不评估高层设计推理，而是隔离并量化底层网表操作的结构性可靠性。
2. **CIRCUIT（Skelic et al., 2025）**：评估 LLM 的电路解释和推理能力。NetlistBench 定位差异：CIRCUIT 关注知识型问题，NetlistBench 关注"读-改-写"操作层面的结构保真。
3. **SPICEPilot / AnalogCoder / Spice Wizard**：依赖仿真反馈循环和工具辅助修复来提升 SPICE 代码/网表生成质量，暗示未经验证的 LLM 输出可靠性不足。NetlistBench 定位差异：直接量化未经修复的原始输出可靠性，为这类修复循环提供必要性依据。
4. **SPICED（Chaudhuri et al., 2024）**：研究 LLM 辅助检测 A/MS 网表中的语法定 Bug 和模拟 Trojan。NetlistBench 定位差异：SPICED 关注异常检测，NetlistBench 关注结构操作的主动可靠性。
5. **Image2Net（Xu et al., 2025）**：用图结构化网表比较而非原始字符串匹配评估原理图→网表转换。NetlistBench 继承这一思想但扩展至网表编辑和复合操作。
6. **SWE-bench（Jimenez et al., 2024）**：通用代码基准，依赖单元测试验证功能正确性。NetlistBench 定位差异：电路表示无法用传统 unit test 验证，需依赖电路结构等价性比较。

## 局限性与未来方向
1. **网表规模有限**：所有测试网表均在模型上下文窗口内，未评估工业级后布局网表（含百万级器件和寄生参数）。
2. **电路域覆盖受限**：主要覆盖扁平/层次 CMOS 模拟块，未全面涵盖 .param 表达式、复杂 .model 卡、受控源、寄生提取、RF/功率/数字/混合信号网表。
3. **指令多样性不足**：任务指令由确定性模板生成，未捕捉真实设计师-助手交互中的语言变异和设计意图。
4. **单次评估**：每个模型-案例对仅评估一次，反映的是 API 快照而非完整输出分布。
5. **未来方向**：开发图结构化的电路表示以直接暴露连接性；设计分解编辑工作流，每一步后结构验证；探索带反馈的迭代编辑机制。

## 研究启发与可借鉴点
1. **结构化验证替代文本/仿真验证**：对于代码/表示类任务，可借鉴 NetlistBench 的 canonical IR 比较思路，用规范结构表示做确定性验证，而非仅依赖字符串匹配或最终仿真。
2. **复合操作长链路评估设计**：将 k 步依赖编辑串联为单一指令，可揭示模型在多步操作中的误差累积特性，适用于评估任何多步代码/配置操作能力。
3. **操作类型分层评估框架**：将任务拆分为"局部替换→连接维持→层次操作→长链路复合"的复杂度梯度，精准定位模型薄弱环节，优于单一的端到端指标。
4. **推理模式的边际收益量化**：通过同一模型在思考/非思考模式下的对比，发现推理对简单任务帮助有限、对结构密集任务帮助显著但对长链路仍不足，为是否启用推理提供实证依据。
5. **可复现的基准发布范式**：NetlistBench 开源了所有案例、确定性生成脚本、评估预言机和提示模板（Apache-2.0 + CC BY 4.0），为领域基准的可复现性树立标杆。

## 关键术语表
**SPICE Netlist**：面向电路仿真器的网表文本描述，通过器件实例、节点名和参数编码电路拓扑结构，电气连接由节点名共享隐式表达。

**Canonical IR（规范电路表示）**：将 SPICE 网表规范化后的内部表示，以结构化的方式列出每个器件的实例名、类型、有序端子节点绑定、参数及层次接口，用于确定性结构比较。

**Structure-Aware Oracle**：基于规范 IR 比较的评估预言机，通过精确匹配设备集、端子绑定、参数和层次接口来验证模型输出的结构正确性。

**Compound Editing（复合编辑）**：将多个相互依赖的编辑操作组合为单一自然语言指令的任务，用于评估模型在多步操作中的结构保真能力。

**Terminal-Node Binding（端子-节点绑定）**：SPICE 网表中器件端子与节点的有序对应关系，是结构性操作必须维护的核心语义。

**VF2 图同构**：用于验证等价判断任务 ground truth 正确性的图同构算法，确认正样本等价、负样本不等价。

**Edit Locality（编辑局部性）**：网表编辑应仅修改目标部分、不影响无关器件和连接的性质，违反局部性是 LLM 操作的典型错误模式。

**Structure-Preservation Bottleneck（结构保持瓶颈）**：模型能生成语法合理的网表，但无法在编辑过程中保持隐式电路图和局部性约束的根本性限制。

## 可复现要素
- **数据集**：NetlistBench 2,342 个案例，已公开于 https://github.com/WoshiMayou/NetlistBench（CC BY 4.0）。
- **代码/权重**：评估预言机、生成脚本、评估运行器和提示模板已开源（Apache-2.0）；LLM 评估通过官方 API 进行。
- **关键超参**：模型以 single-shot 查询，确定性解码，禁用推理模式（除 DS+R 实验外）；重试仅用于传输失败；报告 Wilson 95% 置信区间。
