# 论文速读：NetlistBench-Evaluating-LLM-Reliability-in-SPICE-Netlist-Rec

## 一句话总结
本文提出了 NetlistBench，一个面向 SPICE 网表识别与操作的结构性验证基准测试，用于量化评估 LLM 作为电路设计自动化工作流中网表操作可靠性的表现。结果表明，当前模型在简单局部操作上较可靠（96%–100%），但在涉及拓扑感知、层级操作和长步数复合编辑的任务上存在显著的结构保留瓶颈。

## 研究问题与动机
1. **网表可靠性问题被忽视**：LLM 在电路设计流程中常用于生成、编辑、操作 SPICE 网表，但其作为"模拟器面向表示层"的可靠性从未被直接量化评估，现有工作多关注高层设计推理或端到端仿真结果。
2. **通用代码基准不适用**：传统 LLM-for-code 评测依赖单元测试或仓库测试套件，无法捕捉 SPICE 网表中设备终端语义、共享节点连接性和有序子电路接口等电路特有结构。
3. **现有电路基准未隔离网表操作**：CIRCUIT、AMSbench 等基准评估的是整体电路理解或生成能力，未将"网表结构识别与操作"这一基础操作独立出来作为可量化指标。
4. **结构错误会级联传播**：网表层面的错误会直接污染下游仿真、优化或物理设计，因此可靠的网表操作是实现可信 LLM 辅助电路设计的前提条件。

## 核心贡献（创新点）
1. **将 SPICE 网表可靠性定义为表示层评估问题**：首次提出聚焦于 LLM 能否正确识别和操作网表作为结构化电路工件，而非通用电路知识或格式合规性，与 CIRCUIT/AMSbench 的端到端评估形成定位差异。
2. **构建 NetlistBench 结构性验证基准**：包含 2,342 个样本、24 类任务（800 个识别 + 1,542 个操作），采用确定性模板驱动生成与结构感知 oracle 验证，区别于传统基于字符串相似度或仿真结果的评估方式。
3. **开发基于规范电路表示的结构感知评估管道**：将模型输出与参考目标解析为规范化 IR（隐式图结构编码设备、终端绑定、节点标识、参数和层级），支持 SPICE 与 PySpice 输出的统一评分接口，突破原始文本匹配局限。
4. **揭示长视界复合编辑的可靠性衰减模式**：通过 3/6/9/12/15 步依赖编辑任务，系统性证明模型性能随操作步数增加急剧下降（Claude 从 80% 降至 26%），且推理模式无法根本解决结构保留失败问题。

## 方法详解
**基准构建流程**：
- 数据源：AnalogGenie（平铺 CMOS 模拟网表，492/1752/594 个简单/中/复杂样本）和 ALIGN（层级模拟网表，931 个样本，含 21 种拓扑族）。
- 实例构造公式：每个样本表示为三元组 $J_i = (\mathbf{N}_{\text{src}}^{(i)}, \mathbf{T}_{\text{inst}}^{(i)}, \mathbf{Y}_{\text{target}}^{(i)})$，其中指令和目标是确定性模板生成，确保无歧义。
- 自动化检查：操作目标必须精确实现指定结构变更，识别/等价目标是源网表的规范 IR。

**结构感知评估 Oracle**：
- 将模型输出和参考目标解析为规范 IR，包含：设备名称、类型、有序终端节点、参数、顶层指令、子电路端口接口。
- 匹配规则：设备集合完全一致、终端节点绑定相同、参数数值归一化后相等（如 1k = 1000）、子电路定义在端口接口和内部设备上严格一致；对称两终端器件（电阻/电容/电感）终端无序比较。
- 等价判断任务使用 VF2 图同构算法验证标签正确性，但评分时仍要求保留设备名和节点名。

**任务分类**：
- 识别任务（8 类）：设备参数、语义终端连接、有序终端连接、节点关联、子电路端口、实例端口映射、终端邻居关联、结构等价判断。
- 操作任务（16 类）：连接编辑、设备添加、设备移除、设备替换、参数编辑、命名传播、3/6/9/12/15 步复合编辑、子电路内联展开、端口交换、层级复合编辑。

## 实验与结果
**评测模型**：六款非思维 LLM（Claude Sonnet 4.6、GPT-4.1、Gemini 2.5 Flash、DeepSeek-V4-Flash、Qwen3.6-Flash、Qwen3-30B-A3B），另用 DeepSeek-V4-Flash 开启推理模式作为参考。

**主要结果**：
- **总体准确率**：Claude 最高（82%），GPT-4.1（71%），Gemini 2.5 Flash（64%），DeepSeek-V4-Flash（55%），Qwen3.6-Flash（47%），Qwen3-30B 最低（41%）。
- **简单局部操作**：设备移除（97%-100%）、参数编辑（96%-100%）表现最佳。
- **复杂结构操作**：设备添加（41%-83%）、结构等价判断（49%-90%）显著较低。
- **长视界复合编辑退化**：Claude 从 3 步 80% 降至 15 步 26%；GPT-4.1 从 71% 降至 34%；其他模型在 15 步时接近 0%。
- **推理模式效果**：DeepSeek-V4-Flash 从 55% 提升至 81%，但仍未超过最强非思维模型（Claude 82%），且长步数任务仍显著下降（15 步仅 31%）。
- **PySpice 表示**：对 DeepSeek-V4-Flash 有提升（52%→58%，p<0.001），但对 Qwen3.6-Flash 无效（p=0.51）。

## 相关工作脉络
1. **CIRCUIT [25] / AMSbench [23]**：评估 LLM 的电路拓扑理解与 AMS 域多模态推理能力，定位在高层电路知识，不隔离网表结构操作。
2. **SPICEPilot [26] / AnalogCoder [15] / Spice Wizard [6]**：端到端 SPICE 代码生成系统，依赖仿真反馈或语法检查循环修复，暴露未验证输出的可靠性不足。
3. **SPICED [2]**：检测 A/MS 网表中的语法 Bug 和模拟木马，指出节点、参数、子电路和连接性错误是主要失败类别。
4. **CircuitFormer [11] / Image2Net [31]**：强调标准词法分词与电路图语义的不匹配，使用图结构网表比较而非字符串匹配。
5. **SWE-bench [12]**：通用代码评估基准，依赖单元测试验证功能正确性，无法捕捉 SPICE 网表的设备终端语义和共享节点连接性。
6. **ALIGN [5] / AnalogGenie [7]**：本文基准的数据源，分别提供层级模拟网表和生成式模拟电路拓扑，用于构造识别与操作任务。

## 局限性与未来方向
1. **规模限制**：评估的是电路块级别网表，未测试工业级后版 NETLIST（百万级器件/寄生元件），无法评估长上下文检索、层级分区或直接处理大规模网表的能力。
2. **语法覆盖有限**：主要覆盖 AnalogGenie 和 ALIGN 的平铺/层级 CMOS 模拟电路，未涵盖符号 .param 表达式、复杂 .model 卡、受控源、include 层级、提取寄生参数或特定 PDK 语法。
3. **指令简化**：任务指令由确定性模板生成，未捕捉真实设计师-助手交互的语言变异性与设计意图复杂性。
4. **单次评估**：每模型-样本对仅评估一次，结果反映 API 快照而非完整输出分布。
5. **未来方向**：分解复杂编辑操作、每步进行结构验证、探索显式拓扑的结构化电路表示（如基于图的表示）。

## 研究启发与可借鉴点
1. **结构化验证替代文本匹配**：开发基于规范 IR 的评估管道可精确捕捉结构保留错误，适用于其他结构化表示（如 HDL、电路网表）的 LLM 评估。
2. **长视界依赖编辑作为压力测试**：3/6/9/12/15 步复合编辑任务设计可有效揭示模型在多步操作中的错误累积效应，建议迁移至代码生成、多步推理等场景评估。
3. **推理模式未能根本解决结构保留问题**：表明单纯增强推理能力不足以解决表示层结构性理解缺陷，需结合显式结构约束或工具辅助验证。
4. **数据源复用策略**：AnalogGenie 和 ALIGN 作为公开数据源可直接用于基准构建，模板驱动实例生成方法具有可复现性。
5. **多表示形式对比**：SPICE 与 PySpice 输出对比揭示了不同表示形式对模型表现的差异性影响，可为表示选择提供指导。

## 关键术语表
**SPICE netlist**：面向仿真器的电路描述文本，以位置编码方式记录器件、终端、节点、参数、模型和子电路层级关系。
**Canonical IR（规范中间表示）**：将网表解析为标准化结构，列出所有设备名称、类型、有序终端节点绑定、参数及层级信息，用于确定性结构比较。
**Structure-aware oracle**：基于规范 IR 匹配的评估器，能捕捉设备遗漏、连接丢失、节点重绑定等结构错误，而非仅依赖字符串相似度。
**Long-horizon compound editing**：包含多个相互依赖编辑操作的单指令任务（如 3/6/9/12/15 步），用于测试模型的长期结构追踪能力。
**Terminal-role binding**：器件端口的角色绑定关系，如 MOSFET 的漏极/源极/栅极/衬底对应特定节点，编辑时需保持该绑定。
**Node name sharing**：SPICE 中电气连接通过共享节点名隐式编码，而非显式终端-终端链接，结构分析需从整个网表重建拓扑。
**VF2 graph isomorphism**：用于验证等价判断任务标签正确性的图同构算法，比对设备-网络二分图的结构等价性。
