# 论文速读：Towards-Model-based-Run-time-Cybersecurity-On-Control-Flow-A

## 一句话总结
本文提出一种软硬件协同的运行时安全监控架构：利用软件级观测初步发现控制流异常，再借助独立于被监控软件的硬件级处理器 Trace 获取高保真控制流证据，从而显著提升基于 Attack Tree 的攻击诊断精度，有效对抗攻击者通过篡改软件遥测或隐藏恶意路径实现的“控制流伪装”。

## 研究问题与动机
- 现有运行时控制流异常检测（如 CFI）多依赖软件侧 instrumentation/logging，一旦被入侵，攻击者可轻易篡改或屏蔽观测数据，导致诊断模型输入失真。
- 基于 Attack Tree 的在线诊断高度依赖观测证据质量；当恶意跳转被伪装成维护/调试路径并抹除关键遥测时，诊断树会将高严重性入侵误判为低严重性的配置错误或日志关联问题。
- 攻击者的伪装分为两类：语义伪装（将恶意路径嵌入看似正常的调试/维护流）与遥测伪装（直接篡改软件侧追踪钩子或审计日志），传统单通道观测无法区分两者。
- 需要一种物理上独立、难以被软件栈攻击污染的观测渠道，使诊断模型在对抗环境下仍能输出高可信的根因分类。

## 核心贡献（创新点）
- **提出软硬件双通道控制流观测架构**：软件通道负责广谱异常指示，硬件通道提供独立保真证据；与纯软件 CFI 的本质区别在于证据采集链路物理隔离，规避了软件层被入侵后的观测污染。
- **形式化刻画控制流伪装攻击模式**：将攻击对诊断的干扰分解为对实际执行流的语义伪装与对软件观测通道的遥测伪装，明确界定 $\mathcal{O}_S(\tau) \neq \tau$ 而 $\mathcal{O}_H(\tau) \approx \tau$ 的故障注入场景。
- **揭示 Attack Tree 诊断对观测证据质量的强依赖性**：通过认证服务示例证明，同一诊断树在软件观测与硬件观测下会输出截然不同的根因（低严重性配置问题 vs. 高置信度代码注入/控制流劫持）。
- **将独立硬件监控与可延迟输出缓冲区结合以实现运行时 Containment**：不仅提升诊断精度，还能在检测到异常后阻断可疑输出，将纯检测机制扩展为具备主动隔离能力的闭环架构。

## 方法详解
- **控制流图（CFG）与异常特征向量**：程序建模为 $G=(V,E,v_e,V_f)$，运行时轨迹为基本块序列 $\tau=v_0v_1\dots v_n$。异常特征向量定义为 $F_G(\hat{\tau})=\{\phi_1(\hat{\tau}),\dots,\phi_m(\hat{\tau})\}$，包含缺失块、意外块、非法间接分支目标、源-目标对违规、执行顺序/调用-返回不匹配等。
- **Attack Tree 在线诊断模型**：以观测到的异常为根节点，内部节点为攻击子目标/步骤（AND/OR逻辑）；诊断函数 $D_T(F_G(\hat{\tau})) \subseteq \mathcal{H}$ 将特征向量映射到最可能激活的根因集合。可扩展引入时序算子（SAND）或成本/时间属性支持细粒度推理。
- **双通道观测形式化**：软件观测函数 $\mathcal{O}_S(\tau)=\hat{\tau}_S$，硬件观测函数 $\mathcal{O}_H(\tau)=\hat{\tau}_H$。正常时两者均保真；被入侵后攻击者可污染 $\hat{\tau}_S$，而 $\hat{\tau}_H$ 因独立于软件栈保持高可信。两者差异 $\Delta = \hat{\tau}_H \setminus \hat{\tau}_S$ 本身即构成遥测篡改证据。
- **硬件监控架构三模块**：
  1. *Processor Under Observation (PUO)*：执行应用并产生压缩的硬件 Trace 流（如 ARM CoreSight Program Flow Trace 或 Intel Processor Trace）。
  2. *Cyber-security monitoring engine*：物理隔离于 PUO，不可被其访问；包含 Trace 解压缩与控制流重建单元、预期 CFG 存储、执行监控单元（哈希表常量时间校验非法间接分支目标、缺失/意外源-目标对、地址越界、调用/返回不匹配等）。
  3. *Controllable latency-output-buffer*：置于 PUO 输出路径，仅在无异常信号时释放输出；实现从检测到主动 Containment 的闭环。
- **两阶段协同机制**：软件监控先行触发可疑信号，硬件监控随后对候选事件进行细粒度复核，避免持续全量硬件追踪的高开销。

## 实验与结果
- 本文为概念性与架构设计论文，**未提供大规模基准测试或定量评估数据**。
- 通过自定义工业网关认证服务 Walk-through 示例验证：正常登录路径为 $\langle A,B,C,H,I\rangle$；攻击者利用内存安全漏洞将真实执行流设为 $\tau=\langle A,B,D,E,K,L,M,I\rangle$，其中 $K,L$ 为恶意载荷解码与状态篡改，$M$ 为遥测屏蔽。
- 软件观测还原为 $\hat{\tau}_S=\langle A,B,D,E,F,J\rangle$（伪造维护流程并抹除 $K,L,M$），Attack Tree 诊断为“低/中严重性维护路径误用或日志关联失败”。
- 硬件观测还原为 $\hat{\tau}_H=\langle A,B,D,E,K,L,M,I\rangle$，检测到非法转移 $E\not\to K$、MFA 块 $H$ 缺失及遥测篡改块 $M$ 前置，Attack Tree 正确诊断为“高严重性入侵：从调试路径非法跳转、载荷执行、遥测抑制与 MFA 绕过”。
- 结论：硬件独立观测能显著提升 Attack Tree 诊断的保真度，使相同诊断模型在对抗环境下输出高置信度的真实攻击类；观测差异 $\Delta$ 本身可作为遥测篡改的直接指标。

## 相关工作脉络
- **Control-Flow Integrity (CFI)** (Abadi et al.)：本文以静态 CFG 为基础检测异常，但进一步将 CFI 输出对接 Attack Tree 在线诊断，并聚焦对抗性观测污染场景，而非仅做运行时拦截。
- **硬件辅助 CFI 与 Trace 监控** (Daví et al., Lee et al., Kargos)：本文借鉴基于 CoreSight PT / Intel PT 的离线监控思想，但将其明确纳入“双通道观测+诊断树”的理论框架，并分析伪装攻击下的可监测性差异。
- **Attack Trees / Attack Graphs** (Schneier, Lallie et al.)：本文继承树/图结构表示攻击分解逻辑，但将其从离线威胁建模工具提升为在线诊断引擎，并揭示其对观测通道完整性的强依赖。
- **带有部分可观测性的运行时验证** (Cimatti et al., Ferrando & Malvone, Taleb et al.)：本文指出安全诊断中的“观测被恶意篡改”是该领域对抗性变体，未来可借用 imperfect/partial trace 理论形式化分析监控器的可诊断性边界。
- **非侵入式 Trace 监控架构** (Leucker et al., Weiss 专利)：本文直接延展作者前期在 DX’23 提出的离线 Trace 监控方案，新增 Attack Tree 诊断层与对抗伪装分析，形成完整的运行时 cybersecurity 闭环。

## 局限性与未来方向
- 硬件 Trace 可能因缓冲区溢出、配置错误、动态加载/JIT/编译器优化导致块级映射不完整或失真。
- 强对抗者可能转而攻击硬件监控器固件、Trace 配置或物理平台，独立性假设在特定威胁模型下不成立。
- 运行时处理硬件级 Trace 计算与带宽开销较大，论文承认目前仅实现部分组件，需探索按需触发（软件告警→硬件复核）的两阶段调度策略以降低开销。
- 缺乏对攻击类型、伪装强度与可监测性/可诊断性之间形式化关系的数学刻画。
- 未来方向包括：结合部分可观测性 RV 理论建立诊断不确定性度量；将延迟输出缓冲区与自动缓解策略深度集成；在真实嵌入式/SoC 平台上验证开销与检出率。
