# 论文速读：StrokeGuard-A-Multi-Agent-Guided-System-for-Prehospital-Stro

## 一句话总结
StrokeGuard 是一种面向非临床照护者的多 Agent 引导系统，通过双通道 Agent 机制、状态机编排和分阶段证据管理，使移动 FAST 卒中筛查更加标准化和可执行。

## 研究问题与动机
1. **院前卒中评估准确性不足**：FAST 等筛查工具在家庭/社区场景下，非临床用户常因症状描述不准确、观察不完整、操作困难等因素，导致评估结果有误或偏差。
2. **单 Agent 系统的流程容错缺陷**：传统开放对话 Agent 在院前评估中可能出现"帮助请求被误写为临床证据"（导致提前推进阶段）、"阶段外证据覆盖当前阶段"（导致阶段跳跃）、"单阶段失败扩散至全流程"（导致证据被低优先级文本覆盖）等问题。
3. **现有多模态卒中研究忽略输入可用性**：DeepStroke、M3 Stroke、Digital FAST 等研究聚焦特征提取与分类性能，假设高质量输入已就绪，但未解决低经验用户在应急压力下的交互引导和流程连续性保障问题。
4. **缺少面向多步 AI 引导任务的用户体验评估工具**：现有量表（SUS、NASA-TLX 等）不够贴合多步骤评估任务的交互特性，需要适配任务引导性、步骤感知、支持连续性等维度。

## 核心贡献（创新点）
1. **双通道 Agent 交互机制**：首次将正式评估输入（视频提交、阶段完成事件）与支持性对话（操作指导、问题解答）在权限层面严格分离，支撑渠道的 Agent 无法更改临床状态，从根本上阻断证据误分类。
2. **证据感知编排 + 分阶段本地恢复**：引入有限状态机编排器，基于证据优先级（pending < text < video）进行单调更新，限制故障仅作用于当前阶段，已完成的阶段不被回滚。
3. **面向溯源的结构化交接报告**：每个结论绑定证据模态、来源、处理状态、回退原因和事件历史，支持临床医生事后审查证据链而非仅看最终标签。
4. **提出 MATES-9 用户体验量表**：整合 SUS、NASA-TLX、MAUQ、CUQ/BUS 等构念，形成针对多步 AI 引导任务的探索性评估工具，用于测量任务引导性、信息清晰度、支持连续性、认知/操作负荷和行动-决策支持。

## 方法详解
### 系统架构（三层）
- **用户界面层**：向照护者展示当前阶段、捕获动作和支持性对话。
- **多 Agent 协调层**：双通道决策 Agent 负责路由输入，评估 Agent 引导当前阶段采集，支持 Agent 回答操作/解释/安抚/应急问题。
- **评估与审计层**：调用专用的 Face/Arm/Speech 模块，存储证据来源与处理痕迹。

### 双通道交互形式化
设用户输入 $x_t$，会话上下文 $c_t$，临床评估状态 $s_t$：
$$r_t = R(x_t, c_t), \quad r_t \in \{\text{assessment}, \text{support}\}$$
权限约束：
$$\mathcal{P}(\text{assessment}) = \{\text{create\_event}, \text{write\_evidence}, \text{request\_transition}\}$$
$$\mathcal{P}(\text{support}) = \{\text{read\_context}, \text{generate\_reply}\}$$
状态更新仅当评估事件通过编排器校验：
$$s_{t+1} = \begin{cases} T(s_t, e_t), & r_t = \text{assessment} \wedge V(e_t, s_t) = 1 \\ s_t, & \text{otherwise} \end{cases}$$

### 证据感知编排与分阶段恢复
- 证据槽 $z_k = (y_k, m_k, q_k, \tau_k)$，模态优先级 $\text{pending} < \text{text} < \text{video}$。
- 单调更新规则：新证据仅当优先级不低于当前证据且通过会话/阶段/任务身份校验时写入。
- 阶段推进仅取决于当前阶段是否达到完成条件，与其他阶段无关。
- 故障局部化：视频/音频失败时，仅当前阶段触发 text fallback，已完成阶段不受影响。

### 结构化交接报告
每个评估结果包含：结果字段（阶段结论）、来源字段（证据模态/来源/质量/回退原因）、事件字段（路由/提交/失败/回退/回调/阶段推进），形成可追溯的证据链。

## 实验与结果
### 机制消融案例（Case Study）
- **Case A（无双通道约束）**：开放 Agent 将用户的焦虑提问误写为 Face 异常，导致提前进入 Arm 阶段。StrokeGuard 将提问路由至支持通道，仅生成回复，不改变 Face 证据。
- **Case B（无证据感知编排）**：开放 Agent 允许 Arm 异常覆盖当前 Face 阶段，导致阶段跳跃和证据归属不清。StrokeGuard 拒绝将 Arm 视频写入 Face 槽，保持阶段顺序。
- **Case C（无分阶段恢复）**：开放 Agent 在 Speech 失败后要求用户重新描述所有阶段，且可能用低优先级文本覆盖已完成视频证据。StrokeGuard 仅在当前 Speech 阶段进行 text fallback，保留 Face/Arm 视频证据。

### MATES-9 用户评估
- **场景**：模拟院前卒中场景，专业演员扮演约 70 岁卒中患者。
- **样本**：12 名参与者（20-39 岁，男女各半），分为 StrokeGuard 组与纸质 FAST 表单组。
- **结果**：
  - StrokeGuard 组 MATES-9 总分：$56.33 \pm 5.61$，纸质组：$45.50 \pm 8.22$
  - **绝对提升 10.83 分，相对提升 23.8%**
  - Welch t 检验：$t(8.83) = 2.67, p = 0.026$，Hedges $g = 1.42$（大效应量）
  - 平均评估时间从 116s 降至 81s（**下降 30.2%**）
  - 最大增益领域：低认知/操作负荷、支持连续性

## 相关工作脉络
1. **DeepStroke / M3 Stroke / Digital FAST**：多模态卒中筛查算法研究，聚焦面部/语音/肢体动作的特征融合与分类精度；StrokeGuard 不重新训练分类器，而是封装预训练模块并解决"高质量输入可用性"这一前置问题。
2. **VOICE**：语音 AI Agent 用于模拟院前卒中评估；StrokeGuard 在交互可控性、阶段编排和证据溯源上更为严格，支持视频优先的多模态输入。
3. **Mobile Stroke Units / Dispatcher 识别算法**：面向训练人员的结构化系统；StrokeGuard 面向普通家庭照护者，强调低经验用户友好的流程引导。
4. **MetaGPT / ChatDev**：通用多 Agent 协作框架；StrokeGuard 借鉴角色分工思想，但引入临床安全约束（权限边界、证据优先级、可审计交接）。
5. **SUS / NASA-TLX / MAUQ / Health-ITUES**：通用可用性/工作量量表；StrokeGuard 在此基础上适配出 MATES-9，针对多步 AI 引导任务的任务引导性、步骤感知、支持连续性等维度。

## 局限性与未来方向
1. **样本量小**：MATES-9 实验仅 12 名参与者，统计推断能力有限，需在更大规模样本中验证。
2. **评估模块未充分验证**：Face/Arm/Speech 专用模块的性能、质量控制阈值尚待更真实场景下的验证。
3. **原型阶段**：尚未与调度系统、电子健康记录（EHR）和医院接收系统真正集成，实际部署可行性需进一步研究。
4. **MATES-9 为探索性工具**：量表的信效度需更多实证数据支撑。
5. **未来方向**：在更真实场景中验证评估模块、质量控制阈值、MATES-9 及机制消融效果；研究与他人调度/电子病历系统的集成。

## 研究启发与可借鉴点
1. **双通道 Agent 架构**：将"可改变状态的评估输入"与"仅回答的交互输入"分离，适用于任何需要严格状态控制的医疗/流程引导任务，可复用到手术准备检查、急救流程指导等场景。
2. **证据优先级单调更新规则**：多源证据融合时按优先级严格单向更新，防止低质量数据覆盖高质量数据，可推广至多模态诊断系统。
3. **分阶段本地恢复机制**：将故障影响限制在当前步骤，已完成步骤不回滚，适合任何多步骤采集类任务（如药物筛查、疫苗接种确认）。
4. **MATES-9 量表设计思路**：针对多步 AI 引导任务的用户体验评估框架，整合任务引导性、步骤感知、支持连续性等维度，可复用于其他 AI 辅助评估系统的 UX 研究。
5. **可解释结构化交接**：每个结论绑定证据来源与处理痕迹，便于事后审查，对医疗 AI 的可审计性设计具有参考价值。

## 关键术语表
- **FAST**：Face（面部）、Arm（手臂）、Speech（言语）测试，快速卒中筛查标准流程。
- **双通道 Agent（Dual-Channel Agent）**：将用户输入路由到评估通道（可改变状态）和支持通道（仅回答）的交互机制。
- **证据感知编排（Evidence-Aware Orchestration）**：基于证据优先级和阶段身份控制状态转移的确定性调度逻辑。
- **阶段本地恢复（Stage-Local Recovery）**：故障仅作用于当前阶段，已完成阶段不回滚、不受污染。
- **text fallback**：当前阶段视频/音频录制失败时，允许照护者用结构化文本描述症状作为降级证据。
- **结构化交接（Structured Handoff）**：将评估结论与证据来源、处理状态、事件历史绑定的报告生成方式。
- **MATES-9**：多步 AI 引导任务体验量表，整合 SUS、NASA-TLX 等构念的探索性评估工具。
- **状态机控制（State-Machine Control）**：用离散状态和确定性转移规则管理评估流程，避免开放对话 Agent 的自由发挥。
