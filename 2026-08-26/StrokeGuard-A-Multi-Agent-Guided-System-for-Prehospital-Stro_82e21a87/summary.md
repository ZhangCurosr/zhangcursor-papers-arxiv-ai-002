# 论文速读：StrokeGuard-A-Multi-Agent-Guided-System-for-Prehospital-Stro

## 一句话总结
针对家庭与社区场景下非临床用户难以规范执行FAST中风筛查的痛点，StrokeGuard提出一种多智能体引导系统，通过双通道代理权限隔离、证据感知有限状态机编排与阶段本地回退策略，实现标准化、容错且证据可追溯的院前卒中智能评估交互流程。

## 研究问题与动机
- 现有FAST/CPSS等院前筛查工具依赖专业人员操作，非临床照护者在紧张环境下易出现描述不准确、症状观察不全、操作复杂等问题，导致评估偏差或急救激活延迟。
- 现有AI卒中筛查研究（如DeepStroke、M3 Stroke、Digital FAST）主要聚焦面部/语音/肢体的特征提取与分类精度，隐含“高质量输入已就绪”假设，忽视了模型接收输入前的交互引导与容错缺口。
- 通用对话智能体虽具灵活问答能力，但无法保证结构化评分合规性、多模态输入质量门槛，也难以向临床医生提供可审计的证据来源与状态交接记录。
- 传统单智能体系统在院前评估的程序容错性、中断恢复能力及证据防污染方面存在缺陷，亟需引入确定性编排与角色分离架构。

## 核心贡献（创新点）
1. **提出面向非专业照护者的院前卒中评估多智能体系统**：将FAST式筛查重构为多智能体执行问题，明确划分正式评估、程序支持、阶段推进、本地回退与源保留交接的职责边界。
2. **设计评估智能体的可控执行架构**：解耦自然语言交互、确定性编排与专用评分模块，支持各阶段视频评估算法的模块化替换，并可直接迁移至其他具有固定流程或多项评估的临床筛查任务。
3. **构建针对受控评估智能体的机制验证与评估体系**：通过双通道约束、证据感知编排、阶段本地恢复三项机制消融案例揭示开放域智能体的典型失败模式，并提出MATES-9作为多步AI引导任务用户体验的探索性测量工具。

## 方法详解
- **三层架构**：用户界面层负责展示当前阶段、采集动作与支持通信；多智能体协调层负责输入路由、自然语言交互与确定性状态控制；评估与审计层调用专用Face/Arm/Speech模块并存储证据源与处理轨迹。
- **双通道交互与权限隔离**：引入双通道决策智能体对用户输入$x_t$与上下文$c_t$进行路由，输出$r_t \in \{\text{assessment, support}\}$。评估通道权限集为$\{ \text{create\_event, write\_evidence, request\_transition} \}$，可写入临床证据并触发状态转移；支持通道权限集仅为$\{ \text{read\_context, generate\_reply} \}$，生成回复但不改变临床状态（公式1-3）。该设计防止支持类询问被误判为临床证据导致阶段跳步或重复提示。
- **证据感知编排与阶段本地恢复**：采用有限状态机（患者信息→Face→Arm→Speech→处理→完成）推进任务。每阶段证据槽$z_k = (y_k, m_k, q_k, \tau_k)$按优先级pending < text < video单调更新，新证据仅当模态优先级不降低且通过会话/阶段/任务身份校验时才覆盖原值（公式4），阶段推进仅取决于当前阶段是否达到完成条件（公式5）。媒体失败时，恢复函数$F$仅作用于当前阶段$k_t$（重试、等待或文本回退），已完成阶段不回滚，后续阶段不被污染（公式6-7）。
- **Video-first / Text fallback策略**：优先使用视频证据保留直接临床线索；网络不稳、角度受限或设备故障时，允许照护者以结构化文本描述当前阶段观察，记录较低证据等级与回退原因，实现局部补偿而非全局替代。
- **源保留结构化交接（Source-preserving handoff）**：最终报告通过固定模板组装，将每个结论绑定证据模态、具体来源、处理状态、回退原因及事件历史，使系统行为完全可重构，临床医生可据此区分“视频源异常”与“文本回退异常”并决定是否复采。

## 实验与结果
- **实验设置**：模拟院前发病场景，由约70岁专业男演员扮演卒中患者模拟FAST症状；12名20-39岁参与者（男女各6）随机分为两组，分别使用传统纸质FAST表单或StrokeGuard完成评估，随后填写MATES-9。
- **基线对比**：传统纸质FAST评估表。
- **主要结果**：
  - StrokeGuard组MATES-9总分为$56.33 \pm 5.61$，纸质组为$45.50 \pm 8.22$，绝对提升10.83分，相对提升23.8%。
  - 探索性Welch独立样本t检验：$t(8.83)=2.67, p=0.026$，Hedges $g=1.42$；0-100换算后总分从67.6升至87.7。
  - 平均评估耗时从116秒降至81秒，降幅30.2%；最大增益落在“低工作负载”与“支持连续性”维度。
- **机制消融案例**：
  - Case A（去双通道）：支持类焦虑询问被误写为Face异常证据，导致阶段提前推进。
  - Case B（去证据感知编排）：跨阶段Arm异常视频被错误写入Face证据槽，引发阶段跳步与归属模糊。
  - Case C（去阶段本地恢复）：Speech媒体失败扩散至全流程，并以低优先级文本覆盖已完成Face/Arm视频证据。
  - 三例共同验证了控制机制对临床状态保护、证据归属与故障隔离的关键作用。

## 相关工作脉络
- **DeepStroke / M3 Stroke / Digital FAST**：聚焦多模态特征融合与卒中分类精度，假设输入质量已达标；本文不重新训练分类器，而是将这些算法封装为受限模块，重点解决输入获取、流程控制与证据审计问题。
- **VOICE**：基于语音AI智能体的院前评估原型，具备对话能力但缺乏显式的状态写权限隔离与多模态证据链追踪，难以满足临床可审计要求。
- **MetaGPT / ChatDev**：通用多智能体软件工程框架，强调角色分工与任务组织；本文借鉴其协作思想，但引入确定性工作流状态机、写边界约束与医疗安全规则，区别于开放域LLM的自主编排。
- **移动卒中单元（Mobile stroke units）与调度员识别算法**：前者依赖车载训练人员，后者面向专业调度员；本文面向家庭/社区非专业照护者，解决直接交互式引导、弱网容错与证据保留问题。
- **医疗HCI评估量表（SUS / NASA-TLX / MAUQ / CUQ / BUS）**：现有量表覆盖可用性、工作负荷与聊天机器人界面，但未针对“多步AI引导任务”的步骤感知与支持连续性专门设计；本文据此衍生MATES-9并验证其区分度。
