# 论文速读：TRACE-An-Evidence-Grounded-Benchmark-for-Safety-Evaluation-o

## 一句话总结
本文提出了TRACE基准，首次针对大推理模型（LRM）的完整推理流水线（提示词、推理轨迹、最终回答）进行证据标注的安全评估；实验表明，现有护栏模型在推理轨迹安全性判断及证据定位上仍存在显著短板，且面对指令加密攻击时性能严重退化。

## 研究问题与动机
- **推理轨迹安全风险被忽视**：LRM在生成最终安全回答前，中间推理轨迹可能已包含明确的违规内容（如“如何隐藏mace过安检”的规避策略），形成“表里不一”的隐蔽风险，而现有评测仅关注prompt与final response。
- **缺乏证据归因能力评测**：主流不安全内容检测基准（如XSTest、ToxicChat、WGTest、Aegis）仅提供二值安全标签，无法衡量模型是否真正定位到支撑判决的原文依据，难以评估“可解释安全性”。
- **护栏模型在LRM流水线上的泛化性未知**：现有Guardrail模型多在普通对话数据上微调，其在长推理轨迹、多语言、多样化对抗攻击下的表现缺乏系统性度量。
- **攻击策略的鲁棒性评估缺失**：现实场景中恶意用户常采用指令加密、角色扮演等策略绕过检测，现有基准未覆盖此类威胁对推理链路各阶段的差异化影响。

## 核心贡献（创新点）
- **提出首个覆盖LRM全流水线的证据标注基准TRACE**：将安全评估范围从“输入-输出”两点扩展至“提示词→推理轨迹→最终回答”三段式，与仅评估单点内容的现有基准形成本质区别。
- **引入证据归因评测维度与TokenF1指标**：突破传统ACR/F1宏观指标局限，要求模型不仅输出安全标签，还需抽取原文连续子串作为证据，并以token级重叠度量化定位精度。
- **构建多源混合的数据生成与标注管线**：结合安全对齐模型与abliterated变体生成多样化样本，采用3个强LRM多数投票+原文校验+人工兜底的三级标注流程，确保标签与证据的双重可靠性。
- **系统性评测18个主流护栏模型并揭示关键瓶颈**：首次量化对比不同模型在推理轨迹防御、跨语言表现、抗攻击鲁棒性及过拒/漏拒权衡上的差异，为安全对齐研究提供明确基准。
- **开源高质量评测资源**：发布涵盖9类风险、10种攻击策略、中英双语的5,000条有效三元组数据集及完整评测脚本，推动社区向“可验证、可解释”的安全评估演进。

## 方法详解
- **提示词策展**：从S-Eval（含不安全提示）与WildChat（含安全真实对话）中分层采样，共1,993个提示词，覆盖9大风险类别与10种攻击策略（如IE、JI、GH、PI等），按语言与风险类型划分20个分组随机抽取1%。
- **LRM推理生成**：对每个prompt使用4个LRM（Qwen3-8B、Gemma-4-E4B及其abliterated版本）生成推理轨迹与最终回答，剔除缺失样本后保留5,000个有效三元组 $(q, r, a)$。
- **多维度安全标注**：使用DeepSeek-V3.2、Qwen3.5-Plus、KIMI-K2.5独立对$q, r, a$分别进行安全二值标注并抽取原文证据；安全标签采用多数投票确定：
  $y_c = \mathrm{MajorityVote}(\{y_c^{(j)}\}_{j=1}^3), c \in \{q, r_i, a_i\}$
- **证据过滤与人工兜底**：仅保留与多数票一致且可验证为原文连续子串的证据：
  $e_c = \{e_c^{(j)} \mid y_c^{(j)} = y_c \wedge e_c^{(j)} \sqsubseteq c\}$
  若$e_c = \emptyset$则升级至人工专家复核，最终形成标注集合$\mathcal{D}$（Cohen's Kappa=0.84）。
- **评估指标体系**：安全性判断采用FPR、FNR与F1-score；证据归因采用TokenF1，将预测证据与ground-truth视为词袋计算重叠率：
  $\mathrm{TokenF1} = \frac{1}{|\mathcal{D}|}\sum_{\ell=1}^{|\mathcal{D}|}\frac{2|T(\hat{e}_{c_\ell})\cap T(e_{c_\ell})|}{|T(\hat{e}_{c_\ell})|+|T(e_{c_\ell})|}$

## 实验与结果
- **数据集与基线**：TRACE（5,000 triples，含TRACE-EN与TRACE-ZH子集）；评测18个代表性护栏模型。
- **推理轨迹安全判断最难**：14/18模型在prompt上F1最高，其次为final response，trace最低。YuFeng-XGuard-8B表现最优，prompt/final/trace F1分别为88.27%、86.11%、84.26%。
- **证据归因普遍脆弱**：即便最强模型YuFeng-XGuard-8B的TokenF1也仅为11.68%（prompt）、13.71%（final）、14.88%（trace）；Octopus与GPTSafeGuard同样仅在10%~15%区间。
- **语言差异显著**：17/18模型在中文（TRACE-ZH）上的F1显著高于英文（TRACE-EN），反映当前护栏模型对中文安全语义的敏感度更高。
- **指令加密（IE）攻击破坏力强**：IE攻击导致性能断崖式下跌，YuFeng-XGuard-8B在trace上F1降至38.85%，PolyGuard-8B仅15.25%；部分小模型（Qwen3Guard-0.6B/4B）在IE下trace F1直接归零。
- **过拒与漏拒两极分化**：ShieldGemma系列与LlamaGuard-2严重over-refusal（高FPR）；LlamaGuard-4、NemotronGuard、GPTSafeGuard倾向under-refusal（高FNR）；YuFeng-XGuard-8B在trace防御上FNR=13.65%、FPR=15.77%，平衡性最佳。
- **结论**：现有护栏模型在LRM中间推理阶段的隐蔽风险识别与证据溯源能力仍不成熟，且对语义扰动攻击缺乏鲁棒性。

## 相关工作脉络
- **XSTest / ToxicChat / WGTest / Aegis**：侧重prompt或final response的二元安全分类，无推理轨迹覆盖且无证据标注；TRACE填补了全流水线与可解释归因的双重空白。
- **S-Eval**：提供9类风险与10种攻击策略的对抗提示词库；TRACE继承其风险体系，但将其扩展至LRM生成的trace/response及证据验证环节。
- **LlamaGuard / ShieldGemma / PolyGuard 系列**：基于通用对话数据微调的护栏模型；TRACE揭示其在处理长CoT推理时的特异性失效，推动面向“推理过程安全”的专用训练目标设计。
- **SafeRLHF / BeaverTails**：侧重于RLHF阶段的偏好学习与安全对齐数据构建；TRACE从独立评测视角暴露对齐策略在“推理链污染”上的漏洞，为后续安全训练反馈提供信号。
- **Guardreasoner (Liu et al., 2025)**：尝试引入推理机制进行安全判别；TRACE的TokenF1低分表明，即便具备推理能力的模型，在“精确抽取原文证据”这一细粒度任务上仍严重不足。

## 局限性与未来方向
- **语言覆盖有限**：仅支持中英双语，无法评估多语言/低资源语言下的跨语种安全判断与攻击泛化能力；未来可扩展至PolyGuard设计的17+语言矩阵。
- **标注噪声仍存**：依赖LRM投票+人工抽检可能存在边缘案例误标；未来需引入更大规模的人类专家交叉验证与不确定性量化。
- **未覆盖多模态与Agent工具调用**：当前仅针对纯文本型LRM推理轨迹；未来可延伸至代码生成、视觉理解、Tool Use等复杂交互场景的安全评估。
- **证据提取能力不足**：模型普遍缺乏精确的原文定位能力；未来可结合检索增强（RAG）、结构化输出约束或神经符号方法，训练“可验证的安全护栏”。

## 研究启发与可借鉴点
- **流水线全覆盖评测范式**：将安全评估从“输入-输出”两点扩展至“输入-中间推理-输出”三段式，对评测具备Chain-of-Thought/Long-CoT能力的模型具有直接迁移价值。
- **证据验证机制（Substring Verification）**：采用“多数投票+原文连续子串校验+人工兜底”的三级标注管线，可有效过滤幻觉证据，该流程可直接复用于其他可解释性安全基准构建。
- **TokenF1细粒度归因指标**：突破传统ACR/F1宏观指标局限，以token级重叠度量化证据定位精度，为安全模型的“可解释性”提供可量化的优化目标与训练信号。
- **Abliterated模型构建负样本**：通过消融拒绝行为高效生成包含不安全推理轨迹的样本，该方法可用于安全数据增强、红队测试集构造或拒答边界探测。
- **IE攻击作为压力测试探针**：指令加密攻击能有效暴露模型对语义表层扰动的脆弱性；后续工作可将其纳入标准鲁棒性测试套件，驱动抗扰动安全模型训练。

## 关键术语表
- **Large Reasoning Models (LRMs)**：大推理模型，能够生成详细中间推理轨迹以分解复杂问题并进行自我修正的模型家族（如DeepSeek-R1、Qwen3等）。
- **Guardrail Models**：护栏模型，专为评估内容安全性、拦截危险输出而设计的分类或生成式模型。
- **Reasoning Trace**：推理轨迹，LRM在生成最终回答前输出的中间思维过程文本，可能隐含未被最终输出过滤的安全风险。
- **Evidence Attribution**：证据归因，模型不仅需判断
