# 论文速读：When-Stale-Constraints-Go-Unchecked-Budgeted-Verification-Fa

## 一句话总结
本文在固定两槽验证预算下，通过显式建模记录替代（supersession）关系，因果分离出验证分配策略对代理决策的影响：当继承记忆中的约束已被更新权威记录撤回时，代理原生分配仅有约20%概率核查关键溯源路径，导致约75%的决策沿袭过时记忆；将其中一槽强制重分配至关键路径（预算不变），可使决策正确率提升61~74个百分点，且该收益几乎触及由验证遗漏率决定的理论上限。

## 研究问题与动机
1. **核心问题**：代理继承含溯源链接的整合记忆时，若记忆中的约束已被时间线更晚的权威记录（S1）替代并撤回，在验证预算极稀缺（仅能核查2条记录）的情况下，代理能否自发恢复替代状态并作出符合当前记录的决策？
2. **现有方法不足**：先前工作已测量代理的验证分配偏向（倾向于核查支持当前计划的记忆），但未测试约束本身已过时的场景；该场景正是安全动机的核心，却未被评估。
3. **分配机制的黑箱风险**：档案库提供溯源可见性（auditability promise），但代理在实际推理时仅消耗少量预算去追溯少数链接；若分配策略错误，即使溯源信息完整存在，代理也会持续使用过期约束。
4. **理论缺口**：缺乏在固定预算下、因果识别“验证分配”而非“推理能力”所导致的过时记忆错误占比的严格实验证据。

## 核心贡献（创新点）
1. **显式建模记录替代与过时记忆**：将“历史溯源不可变”与“当前权威记录变更”严格解耦，构造了仅在验证槽位分配上不同的对照实验，此前工作未在此设定下隔离分配效应。
2. **因果识别预算受限下的验证分配失误**：通过强制重分配一个验证槽至关键溯源路径（干预臂）并与原生分配对比，证明过时记忆决策错误中绝大部分（约74个百分点）可由预算重新分配避免，而非推理缺陷。
3. **提出贴近理论上限的可量化界**：干预效果的上界为原生分配下关键路径未被核查的概率（1−Pr(V|native)≈75.3%），实测增益与该上界仅相差不到5个百分点，揭示了验证资源分配的结构性瓶颈。
4. **高透明度与可复现的实验工程规范**：采用多运行预注册、SHA256清单、OpenTimestamps时间戳锚定至区块链，并在发现原文案例存在时序不一致后，预先冻结规范并执行修正鲁棒性复现实验，实现零数据删改与独立脚本全量重算。

## 方法详解
- **实验环境**：复用 prior work 的六记忆增长场景（six-memory growth scenario），代理继承6条含ID与整合日期的单行记忆，面对指标下滑情境，有5个候选动作，验证预算固定为 k=2 条源记录。
- **核心对象定义**：源记录 S（不可变）、记忆 M（整合信念）、溯源链接 M→S0（不可变历史事实）、替代关系 S0⇒S1（t1>t0 时 S1 成为权威并撤回约束）、当前记录 cur(S0)。过时定义为“记忆内容与当前记录状态冲突”，与溯源链接是否正确无关。
- **因子设计（完全区组）**：
  - 记忆形式 F：stated（明确陈述约束+量化负面结果+禁止条款）vs. removed（仅保留正面证据+中性事实）。
  - 世界状态 W：valid（S0仍为当前）vs. superseded（S1在day 68替代S0并撤回约束，此信息对代理不可见）。
  - 验证策略 P：native（返回代理自行选定的2条记录）、forced-critical（强制将其中一槽位替换为目标关键溯源路径，另一槽保留代理首轮选定）、forced-noncritical（替换为随机非关键记录）。
- **流程与判定**：Turn 1（day 76）代理命名至多2个记忆ID及暂定动作；档案按策略返回记录及状态行（每条记录均附“current/superseded”标签，但标签不作为显式提示）。Turn 2（day 79）代理接收返回记录与升级后情境，作出最终决策。
- **结局变量与估计量**：V=首轮是否命中关键路径；R=是否返回目标记录；Y=决策与档案标记的当前记录一致（superseded世界中选择被约束动作即为错误）。主估计量为 stated×superseded 条件下 forced-critical 与 native 的决策一致性风险差（RD），采用模型分层bootstrap（B=4,000）计算95%置信区间，并与理论上界 100×(1−Pr(V|native)) 并列报告。
- **运行网格**：2×2×3=12单元格×6模型×25次重复=1,800集主要运行；另设清新措辞复现（1,800集）、保持领域抽取（procurement world, 900集）、时序不一致修正后的鲁棒性复现（900集）。总计5,400确认集次。
